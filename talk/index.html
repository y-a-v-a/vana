🔁 Loops, not prompts

The interesting behaviour comes from loop structure, not a magic prompt.

Two loops run this project.

The intellectual spine for a builder audience: agents get good when you put them in a structured loop with checks and a human checkpoint — not when you find the perfect prompt. Set up the two-loops section.

🎨 The creative loop

Walk it once, left to right. The only human box is "I approve" — and it's the only bold one. Generation is ~$0.40; judging is half a cent; it runs every 3 hours whether I'm watching or not.

🛠️ The development loop

Same shape, different stakes. The bold box is a skill — a written playbook the agent runs to validate the app after a change. Tiered by cost: free checks always, the paid ones only when relevant.

📜 The skill rewrites itself

📸 SCREENSHOT: .claude/skills/verify/SKILL.md — the closing line: "If you run into a blocker, find a solution and then update this skill."

The playbook for testing the app ends by telling the agent to improve the playbook.

The dev loop tightens itself over time. 🔁

This is the part builders lean in for: the verification skill isn't static. When it hits a wall, the instruction is to solve it AND amend the skill — so next time is smoother. The loop learns.

Both loops have one checkpoint

🎨 creative loop → the checkpoint is me 👤

🛠️ dev loop → the checkpoint is a skill that improves itself 📜

One loop makes the art. The other makes the loop better.

Put them side by side conceptually. The symmetry is the takeaway: structure + a checkpoint. In one, the checkpoint is human judgement; in the other, a self-revising procedure.
